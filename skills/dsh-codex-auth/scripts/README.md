# Вспомогательные скрипты

POSIX (macOS/Linux), Python 3.9+, PyYAML; для входа также Node.js/npx и локальный интерактивный терминал. Windows не поддерживается скриптом записи: потребуется реализация с проверкой ACL.

Скрипты **не запускают DSH, не меняют модель по умолчанию и не делают платные запросы**. `login.sh` запускает внешний pi-ai CLI; его вывод предназначен только для локального терминала пользователя, не для захвата агентом или публичного журнала.

## 1. Зависимости

В своём терминале создайте отдельное окружение вне репозитория:

```bash
python3 -m venv ~/.venvs/dsh-codex-auth
~/.venvs/dsh-codex-auth/bin/python -m pip install 'PyYAML==6.0.3'
```

Далее `PYTHON` означает Python из этого окружения:

```bash
PYTHON="$HOME/.venvs/dsh-codex-auth/bin/python"
```

## 2. Логин

Из корня репозитория:

```bash
bash skills/dsh-codex-auth/scripts/login.sh 1.3.0
```

Версию pi-ai сначала сверьте с установленной в DSH. По умолчанию используется `1.3.0`, проверенная при первоначальной настройке; это не обещание совместимости с любой сборкой.

После подтверждения скрипт запускает опубликованный pi-ai CLI, а не собственную реализацию OAuth. `npx` может загрузить пакет и его зависимости. Авторизация и возможные ошибки отображаются только в локальном терминале. Скрипт создаёт приватный временный каталог, выводит путь к `auth.json` и оставляет файл для импорта.

**Не отправляйте содержимое файла или callback URL в чат.** Логин по сети не входит в offline-тесты скриптов этого репозитория.

## 3. Импорт и маршрут

Полностью закройте DSH и другие процессы, пишущие в его credentials/config. Скрипт не использует внутреннюю блокировку DSH: флаг `--dsh-stopped` — ваше подтверждение, а не автоматическая проверка процессов.

Пример для стандартного Desktop-профиля; пути сначала проверьте. Если `DSH_HOME` или путь credential provider переопределены, укажите реальные пути.

```bash
AUTH_FILE="/absolute/path/from-login/auth.json"
DSH_DIR="${DSH_HOME:-$HOME/.dsh}"
SCRIPT="skills/dsh-codex-auth/scripts/configure.py"

# Без записи: проверить источник и целевой документ.
"$PYTHON" "$SCRIPT" import-grant \
  --auth-file "$AUTH_FILE" --credentials "$DSH_DIR/.credentials.yaml"
"$PYTHON" "$SCRIPT" configure-route \
  --patch "$DSH_DIR/profiles/desktop/cordis.patch.yml"

# Применить после проверки обоих dry-run.
"$PYTHON" "$SCRIPT" import-grant \
  --auth-file "$AUTH_FILE" --credentials "$DSH_DIR/.credentials.yaml" \
  --apply --dsh-stopped
"$PYTHON" "$SCRIPT" configure-route \
  --patch "$DSH_DIR/profiles/desktop/cordis.patch.yml" \
  --apply --dsh-stopped
```

Для Web-профиля выберите его patch вместо Desktop. Нужны уже существующие credential store и запись `llm-pi-ai`; скрипт не создаёт новый профиль. Существующие Codex grant/route не перезаписываются.

Каждая операция независима. Если импорт прошёл, а правка маршрута нет, grant остаётся в хранилище: исправьте только маршрут или откатите импорт. Не запускайте повторный импорт вслепую.

Запись атомарная, рядом сохраняется уникальный бэкап с правами `0600`. Смысл остальных YAML-полей сохраняется, **форматирование и комментарии нормализуются PyYAML**; оригинальные байты остаются в бэкапе. Неизвестные теги (например, `!!js`) и повторяющиеся ключи отклоняются без записи. Для таких профилей используйте штатный редактор DSH или отдельное точечное редактирование после чтения файла.

Скрипт отказывается обрабатывать symlink/hardlink-файлы, секреты с групповым/публичным доступом и просроченные grant. Контроль изменения файла перед заменой — дополнительная проверка, **не полноценная межпроцессная блокировка**. Родительские каталоги должны быть доверенными и недоступными для записи другим пользователям.

## 4. Проверка и очистка

Запустите DSH, выберите реально доступную модель `openai-codex` и отправьте один короткий запрос. Это потратит немного квоты подписки. Дождитесь завершённого ответа, а не только начала стрима.

После успешной проверки удалите временный `auth.json` локально, предварительно проверив полный абсолютный путь. Бэкап credentials тоже содержит секреты — удаляйте его отдельно после принятого решения об откате. Скрипты намеренно не удаляют ваши файлы автоматически и не отзывают grant на сервере.

## Offline-тесты

```bash
"$PYTHON" -m unittest discover -s skills/dsh-codex-auth/scripts -p 'test_*.py' -v
bash -n skills/dsh-codex-auth/scripts/login.sh
```

Тесты используют синтетические значения в новых временных каталогах и не читают реальные credentials DSH. Они проверяют dry-run, сохранение полей, права бэкапа, отказ при дубликатах/конфликтах/невалидных данных и отсутствие секретов в диагностике. Они не доказывают работоспособность будущих OAuth endpoint или refresh.
